# 派单模板（人类复制粘贴给 openclaw）

**开工**
```
按 cppviz/DEVLOG.md 执行任务 <T编号>。
只读 DEVLOG.md 和该任务涉及的文件，不要读 PLAN.md 全文。
完成后按协议更新 DEVLOG 的 §1/§7/§8。预算 <N>k token。
```

**任务失败/要换方案**
```
T<编号> 遇到问题：<一句话现象>。
先更新 DEVLOG §6（记下这个坑）和 §1（标记阻塞），再给两个备选方案，不要直接改代码。
```

**收尾校验**
```
读 cppviz/DEVLOG.md §1，跑一遍 §1 里写的验证命令，确认与实际一致。
不一致就修正文档，不要改代码。
```

## 派单硬规矩（踩坑总结，K21–K32）

1. **必须带 `--thinking off`**：默认思考会吃光 8192 输出预算，整轮作废。
2. **单 ≤2–3 个文件**，单条工具调用 ≤40 行；不许"一次写完整个文件"。
3. 派单前 `pkill -9 -f "openclaw agent"`，残留进程会占住会话导致新单 `aborted`。
4. 验收标准写**可执行命令 + 期望输出**，不要写"看起来对"。
5. 禁止它跑会卡死的测试时，明确写"不要跑 X，我自己验"。
